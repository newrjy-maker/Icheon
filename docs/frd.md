# 이천 모험지도 기능정의서 (FRD)
상태: 완료

## ⓪ 범위 요약

- **현재 초안 규모:** 필수 하위 기능 65개, 부가 하위 기능 9개
- **예상 개발 작업 규모:** 큼. 실제 구현은 환경 설정, 데이터 입력, 테스트와 현장 QR 검수 작업이 더해져 기능 수보다 늘어난다.
- **복잡도를 높이는 요인:** 비밀번호 없는 아이디 로그인 위험, 선택 이메일 인증·일회용 링크, 삭제 코드, QR 순서 검증과 중복 보상 방지, 3/3 완료와 히든맵 해금의 동시 처리, 장소·운영 정보 검수
- **콘텐츠 기준:** 1차 출시는 동 도자 예술·북 서희 역사 2맵과 QR 6곳을 활성화하고, 서 공룡·남 시몬스 2맵은 잠김·준비 중으로 노출한다. 목표 맵도 현장·이동·QR 검수 전에는 잠금을 유지한다.
- **줄인다면 이 순서로:**
  1. 인트로·깨짐 맛보기를 부가로 이동 — 도자기 시작 연출은 사라지지만 QR→조각→해금 핵심 루프는 유지된다.
  2. MY의 전체 완성률·조각 상세·날짜별 이력을 부가로 유지 — 이어하기와 계정 관리는 남지만 수집 전시 기능이 줄어든다.
  3. 선택 복구 이메일·일회용 로그인 링크를 후속으로 이동 — 이메일 시스템이 빠져 개발량은 크게 줄지만, 아이디를 잊은 사용자는 계정을 복구할 수 없다. 기존 PRD의 P0 결정을 바꾸므로 사용자 승인 없이는 이동하지 않는다.

## ① 요약

이 문서는 확정된 PRD와 디자인 8장을 실제 개발 단위로 분해한다. 서비스의 필수 흐름은 '아이디 가입·복원 → 가족 조건 선택 → 활성 지역 맵 선택 → 현재 맵 3곳의 현장 QR 인증 → 조각 3/3 → 30분 이상 히든맵 해금 → 재접속 후 반복'이다.

- 공개명은 **이천 모험지도**이며 기존 만화·게임 IP를 사용하지 않는다.
- 방문 인증은 현장 QR만 사용하고 GPS 위치 권한·경로 저장은 제공하지 않는다.
- 맵은 서로 다른 스팟 정확히 3곳과 권장 방문 순서를 갖고, 세 장소 QR은 어느 순서로든 인증할 수 있다.
- 운영정보가 확인되지 않으면 추정값 대신 **검수 필요**를 노출한다.
- 사용자 직접 식별정보는 가입 필수값으로 받지 않는다. 선택 이메일은 복구 용도로만 쓴다.
- 관리자 포털은 제외 범위다. 다만 장소·맵·퀘스트·QR을 배포 데이터로 갱신하고 검증하는 비화면 운영 기능은 필요하다.

## PRD·시안 대조 기록

| 구분 | 발견한 차이 | 현재 초안 처리 | 결정 |
|---|---|---|---|
| 시안에만 있음 | 도자기 인트로와 세 조각 깨짐 맛보기 | F1의 부가 기능이자 PRD P1로 반영 | 확정 |
| PRD에 있으나 독립 시안 없음 | 복구 이메일 인증, 일회용 로그인 링크, 삭제 코드 확인, 계정 삭제 | MY·계정 설정 화면의 필수 하위 상태로 구현 | 확정 |
| PRD에 있으나 독립 시안 없음 | 카메라 권한 거부, 잘못된·만료 QR, 순서 오류, 오프라인 재시도 | QR 화면의 필수 오류 상태로 구현 | 확정 |
| 시안으로 구체화됨 | 스팟 상세의 정상 운영·오늘 휴무·검수 필요 | PRD의 스팟 상태 규칙과 일치하므로 필수에 포함 | 반영 |
| 새로 필요 | 관리자 포털 없이 장소·맵·퀘스트·QR·출처를 갱신 | 배포용 데이터 입력·검증 도구와 QR 발급 절차를 필수 숨은 기능으로 포함 | 확정 |
| 일치 | QR 단독, 3곳 권장 순서, 3/3, 30분+ 히든맵, 호법JC 4방 허브 | 그대로 기능 트리로 분해 | 반영 |

## ② 기능 트리

'필수'는 1인 MVP에서 동작해야 하는 범위이고, '부가'는 핵심 루프를 끊지 않고 후속으로 옮길 수 있는 범위다. 필수 기능에는 사용자가 들어가는 화면을 함께 적었다.

### 의존성 점검

- F4 QR 완료 처리는 F1 계정, F2 현재 맵, F7 활성 QR 데이터가 모두 준비돼야 한다.
- F5 해금은 F4의 중복 없는 완료 기록과 F7의 검수된 맵 연결이 필요하다.
- F6의 부가 수집 화면은 필수 진행 데이터를 읽기만 하므로 필수 기능이 부가 기능에 의존하지 않는다.
- F9 계절맵이 없어도 F1~F8의 상시 코어 루프는 동작한다.

## ③ 핵심 기능 대표 시나리오

### 시나리오 A. 아이디 가입·재접속

- **시작 조건:** 사용자가 첫 방문 또는 다른 기기에서 계정·시작 설정 화면을 연다.
- **정상 흐름:** 서비스 아이디 입력 → 형식 검사 → 아이디 조회 → 기존이면 즉시 진행 복원, 신규면 생성 확인 후 계정·빈 진행 생성 → 가족 조건 선택 → 허브 진입
- **대표 예외:** 이메일·전화번호 형식 차단, 존재하지 않는 복구 이메일, 삭제 중 계정, 과도한 로그인 시도
- **완료 기준:** 허브에 계정의 현재 맵·조각·해금 상태가 표시된다.
- **데이터 변화:** 신규 계정은 Account·UserMapProgress 초기값 생성, 기존 계정은 최근 접속 시각과 세션만 갱신
- **사용자가 보는 결과:** 신규는 0/3 시작 상태, 기존은 '이어하기: 맵명 n/3' 상태
- **화면 정책:** 입력창은 하나다. 존재하는 아이디는 즉시 로그인하고, 없는 아이디는 신규 생성 확인을 거쳐야 가입된다.

### 시나리오 B. 두 번째 QR 완료와 세 번째 QR의 히든맵 해금

- **시작 조건:** 로그인 계정이 활성 맵에 포함된 장소 하나에서 QR 스캔을 시작한다.
- **정상 흐름:** 카메라 권한 → 토큰 인식 → QR 활성·장소·퀘스트·순서 검증 → 완료·조각·진행도를 한 번에 저장 → 3초 이내 보상 표시 → 3/3이면 연결 히든맵 활성화
- **대표 예외:** 등록되지 않은 QR, 비활성·교체 QR, 다른 맵 QR, 네트워크 단절, 같은 QR 반복
- **완료 기준:** 같은 요청은 여러 번 도착해도 조각이 한 번만 늘고, 3/3일 때 지정 히든맵이 정확히 한 번 열린다.
- **데이터 변화:** UserProgress 생성, UserMapProgress 조각 수·상태 갱신, 3/3이면 다음 UserMapProgress 활성 행 생성
- **사용자가 보는 결과:** 1/3·2/3이면 다음 장소 안내, 3/3이면 맵 복원·안개 해제와 '지금 시작/다른 날' 선택

## ⑦ 표준 적용 항목과 이유

아래는 화면 선택이 아니라 안전한 서비스의 기본값이므로 기술 방식은 다음 TRD에서 정한다.

- **서버 측 입력 검증:** 브라우저 검사를 우회해도 잘못된 아이디·QR 요청을 막는다.
- **세션 보호와 만료:** 공유 기기에서 이전 계정이 계속 열리는 위험을 줄인다.
- **속도 제한:** 아이디 추측·이메일 링크 남발·QR 반복 요청을 완화한다.
- **단방향 해시:** 삭제 코드 원문 유출을 막는다.
- **일회용·만료 링크:** 오래된 이메일 링크 재사용을 막는다.
- **QR 불투명 토큰:** 장소 ID나 관리자 정보가 QR 문자열에서 노출되지 않게 한다.
- **멱등 처리:** 같은 완료 요청이 반복돼도 결과가 한 번만 반영되게 한다.
- **원자적 저장:** 퀘스트 완료·조각 증가·히든맵 해금 중 일부만 저장되는 상태를 막는다.
- **삭제 지연·백업 만료:** 실수 복구 여지와 삭제 약속을 함께 관리한다.
- **접근성 표준:** 키보드·스크린리더·모션 축소·확대에서도 핵심 행동이 가능하게 한다.

## ⑧ 입력 검증·오류 표시·권한의 공통 동작 규칙

1. 오류는 입력란 또는 실패한 행동 가까이에 아이콘·원인·다음 행동을 함께 표시한다.
2. 아이디는 앞뒤 공백을 제거하고 허용 길이·문자를 검사한다. 이메일·전화번호 형태는 가입 아이디로 받지 않는다.
3. 같은 아이디의 대소문자·유니코드 정규화 정책은 TRD에서 하나로 고정해 중복 계정을 막는다.
4. 카메라 권한은 QR 화면의 버튼을 누를 때만 요청한다. 거부 시 브라우저 설정 안내와 재시도만 제공한다.
5. 네트워크 실패 시 사용자가 재시도할 수 있게 하되 완료 버튼을 연타해도 보상이 늘지 않는다.
6. 현재 지역 맵에 없는 QR은 완료하지 않고 인증 가능한 세 장소를 알려준다.
7. 휴무·운영 중단·검수 필요는 색상뿐 아니라 라벨과 아이콘으로 구분한다.
8. 일반 사용자는 자신의 계정과 진행만 읽고 삭제할 수 있다. 다른 사람의 데이터 검색 기능은 제공하지 않는다.
9. 콘텐츠 운영자는 공개 데이터 파일과 배포 절차만 다루며 일반 사용자 진행을 임의 수정하지 않는다.
10. 계정이 삭제 대기 또는 삭제 완료 상태면 새 세션과 QR 완료를 차단한다.

## ⑨ 비개발자가 눈으로 확인 가능한 인수 기준

- 새 아이디로 시작하면 빈 0/3 계정이 생기고, 같은 아이디를 다른 기기에서 입력하면 같은 진행이 보인다.
- 존재하지 않는 아이디는 확인 창에서 승인해야만 생성되고, 취소하면 계정이 생기지 않는다.
- 이메일이나 전화번호 형태를 아이디로 입력하면 가입되지 않고 이유가 바로 표시된다.
- 허브의 활성 맵 카드마다 서로 다른 장소 3곳, 권장 1→2→3 동선, 차량·도보·유모차 뱃지가 보인다.
- 검수 미완료 또는 스팟 중단 맵은 시작할 수 없고 잠김 이유가 보인다.
- 스팟 상세에서 정상 운영·오늘 휴무·검수 필요가 아이콘·문장·버튼 상태로 구분된다.
- QR 이외의 GPS 자동 완료 버튼이나 위치 권한 요청이 없다.
- 현재 지역 맵의 세 장소 QR은 어느 곳부터 스캔해도 완료되며, 다른 맵 QR만 완료되지 않는다.
- 같은 QR을 두 번 스캔해도 조각이 한 번만 늘어난다.
- 유효한 QR 완료 후 3초 안에 보상 화면이 시작되고 진행도가 즉시 갱신된다.
- 세 번째 서로 다른 QR 완료 후 지역 퍼즐이 3/3이 되고 지정 히든맵이 정확히 한 번 열린다.
- '다른 날'을 선택하고 다시 로그인해도 해금 맵이 유지된다.
- 카메라 거부·잘못된 QR·오프라인 상황마다 원인과 재시도 방법이 보인다.
- 모션 축소 설정에서는 플래시·회전 없이 최종 보상과 진행도가 바로 보인다.
- 계정 삭제는 이메일 링크 또는 가입 시 받은 삭제 코드 없이는 실행되지 않는다.
- 운영 화면 없이도 검수 데이터 파일을 바꾸어 맵·퀘스트·QR 활성 상태를 안전하게 배포할 수 있다.
